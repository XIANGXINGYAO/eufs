脚本没有只检查包名：它还执行了以下真实编译链：

1. 用 `protoc` 生成 `probe.pb.h/.cc`。
2. 编译并链接同时使用 protobuf、gflags、leveldb、OpenSSL 和 pthread 的 C++ 程序。
3. 编译包含 `<fuse3/fuse.h>` 的程序，并使用 `pkg-config` 的 FUSE3 参数链接。
4. 运行两个探针程序并清理 guest 临时目录。

## 安装的依赖

用户态新增的最小开发依赖为：

```text
protobuf-compiler protobuf-devel
gflags-devel
leveldb-devel
openssl-devel
pkgconf-pkg-config
ninja-build
```

dnf 实际额外安装了 protobuf、gflags、leveldb、Abseil、zlib-devel 及少量系统依赖，总下载约 23MB，安装后约 103MB。没有在宿主机安装任何依赖。

openEuler 的 protobuf pkg-config 输出包含 Abseil 传递链接项，因此项目构建不能把 `-lprotobuf` 当成完整链接命令；应优先使用 brpc/CMake 的 imported target，或至少使用 `pkg-config --libs protobuf`。这一点已在门禁中实际暴露并修正，不能遗漏。
