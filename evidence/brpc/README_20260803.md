## 4. 官方 echo 构建

示例使用 Apache brpc 该 commit 自带的 `example/echo_c++`，独立构建目录为
`/root/brpc-lab/echo-build`。首次配置命令为：

```bash
cmake \
  -S /root/brpc-lab/brpc/example/echo_c++ \
  -B /root/brpc-lab/echo-build \
  -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DBRPC_INCLUDE_PATH=/root/brpc-lab/build/output/include \
  -DBRPC_LIB=/root/brpc-lab/build/output/lib/libbrpc.a
```

配置退出码为 `0`。随后执行：

```bash
ninja -C /root/brpc-lab/echo-build -j2
```

首次链接退出码为 `1`。根因不是 brpc 库编译失败，而是 openEuler 的
Protobuf 4.25.1 依赖 Abseil；官方示例 helper 的链接行只有
`/usr/lib64/libprotobuf.so`，没有 Protobuf pkg-config 给出的 Abseil 传递链接项，
因此链接器报告：

```text
undefined reference to ... absl ... LogMessage ...
libabsl_log_internal_message.so.2308.0.0: error adding symbols:
DSO missing from command line
```

修正依据是该系统上的结构化依赖查询：

```bash
pkg-config --libs protobuf
```

其结果除 `-lprotobuf` 外包含所需 Abseil 库。未修改官方示例源码，使用以下
命令把完整传递依赖放到 C++ 最终链接尾部：

```bash
cmake \
  -S /root/brpc-lab/brpc/example/echo_c++ \
  -B /root/brpc-lab/echo-build \
  -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DBRPC_INCLUDE_PATH=/root/brpc-lab/build/output/include \
  -DBRPC_LIB=/root/brpc-lab/build/output/lib/libbrpc.a \
  -DCMAKE_CXX_STANDARD_LIBRARIES="$(pkg-config --libs protobuf)"
ninja -C /root/brpc-lab/echo-build -j2
```

修正后重新配置退出码为 `0`，echo 构建退出码为 `0`。

## 5. 官方 echo 往返

最终有效的 server/client 命令为：

```bash
cd /root/brpc-lab/echo-build
./echo_server --listen_addr=127.0.0.1:8017 > echo-server-run-final.log 2>&1 &
server_pid=$!
./echo_client \
  --server=127.0.0.1:8017 \
  --interval_ms=200 \
  --timeout_ms=1000 \
  > echo-client-run-final.log 2>&1 &
client_pid=$!
kill -INT "$client_pid"
wait "$client_pid"
client_rc=$?
kill -INT "$server_pid"
wait "$server_pid"
server_rc=$?
```

实际控制脚本在 server 日志出现 `is serving on` 后才启动 client，并在 client
日志出现 `Received response from` 后才发送 `SIGINT`。最终结果为：

```text
SERVER_READY=1
RPC_RESPONSE_OBSERVED=1
CLIENT_EXIT_CODE=0
SERVER_EXIT_CODE=0
```

server 收到请求正文 `hello world`，client 收到响应正文 `hello world`。

一次更早的运行把 `--listen_addr` 错写为裸 `127.0.0.1`，官方
`str2endpoint` 拒绝该参数，server 退出码为 `255`，client 未启动。改为完整
endpoint `127.0.0.1:8017` 后通过；该参数失败也保留在原始证据中。

  本次不再清理或修改任何宿主环境内容。
